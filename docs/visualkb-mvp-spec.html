VisualKB Product Spec

VisualKB MVP Spec

VisualKB is an LLM Wiki with HTML: it keeps OpenKB's compiled, source-linked wiki model, then adds renderable HTML Knowledge Objects so complex knowledge can be stored as text, DOM, tables, charts, timelines, diagrams, and screenshots.

Product name: VisualKB Category: LLM Wiki with HTML MVP target: HTML alongside Markdown Updated: 2026-05-11

Context

Karpathy's LLM Wiki idea and OpenKB both point toward compiled knowledge that accumulates over time. The VisualKB fork starts from that base, but treats Markdown as only one representation. The product bet is that HTML is a better artifact when the knowledge includes charts, visual comparisons, architecture maps, screenshots, and multimodal evidence.

MVP Goals

The first version should prove the HTML artifact loop without breaking the existing OpenKB workflow.

1Compile HTML objects

Generate static HTML pages for summaries, concepts, and saved explorations.

2Keep source traceability

Preserve source files, page paths, citations, and inference markers in each object.

3Use visual knowledge components

Support matrices, timelines, flow diagrams, source strips, and data-backed tables.

4Stay compatible

Leave Markdown wiki generation intact while adding HTML as a target.

5Render and lint

Validate links, alt text, data references, responsive layout, and missing citations.

6Make it inspectable by LLMs

Keep visible text, semantic sections, and optional JSON metadata inside the page.

Target Flow

VisualKB should reuse OpenKB's ingestion and concept compilation first, then add an HTML rendering pass. This limits risk and keeps upstream OpenKB behavior available.

01Raw source

PDF, docs, Markdown, web pages, tables, images, and local files.

02Convert/index

MarkItDown or PageIndex creates source text, images, and long-doc summaries.

03Compile wiki

LLM creates summaries, concepts, backlinks, and index records.

04Render HTML

VisualKB renderer maps wiki objects into HTML Knowledge Objects.

05Validate

HTML lint plus screenshot checks catch broken links and layout failures.

CLI Surface

The smallest product surface is a target flag and config entry. The default can remain Markdown until the fork is ready to switch defaults.

Command or configBehaviorMVP note
openkb init --target bothCreate wiki/ and html/ trees.Interactive init can ask later; flag is enough for first pass.
openkb add file.pdf --target htmlCompile source, then render HTML summary/concept pages.Use existing Markdown compiler output as intermediate in MVP.
openkb render-htmlRebuild HTML from the current wiki without re-ingesting sources.Useful for template iteration and regression tests.
openkb lint --target htmlRun path, source, accessibility, and layout checks.Markdown lint remains separate.
.openkb/config.yamltargets: ["markdown", "html"]Use list form so future targets can be added.

File Layout

Implementation Phases

The first implementation should ship in small, verifiable layers rather than rewriting OpenKB's compiler.

Phase 0
Docs and fork intent

Record origin, object schema, MVP scope, and OpenKB integration notes.

Phase 1
Static renderer

Build a renderer that converts existing Markdown summaries and concepts into HTML objects with source strips.

Phase 2
Compiler prompts

Add HTML-aware prompt contracts that can request structured sections and visual component hints.

Phase 3
HTML lint and screenshots

Check links, alt text, missing source strips, data references, and responsive rendering.

Phase 4
Query integration

Let the agent read HTML objects as DOM/text and optionally inspect screenshots or extracted images.

Non-Goals

These are intentionally out of scope for the MVP so the first product loop stays small.

No full web app yet

Static HTML is enough to test the knowledge artifact model.

No Markdown removal

Markdown stays as the compatibility layer until HTML output is proven.

No fake dashboards

Charts and metrics must be source-backed or clearly labeled as illustrative.

Acceptance Checks

The MVP is real when it can produce and validate a small HTML KB from source files.

CheckExpected result
Initialize a KB with HTML targethtml/ directories and an HTML index are created.

Ask a queryThe agent can use existing wiki content and reference HTML artifacts where available.
